# 技术不变量（INVARIANTS）

> **这是什么**：记录项目里「任何时刻、任何代码路径都必须成立」的技术约束——一旦破坏即 bug、且容易被后续改动无意修坏的不变量。
> **与 `business-rules.md` 的区别**：业务规则误判的是**可达性**（软约束，审查 Gate 拦）；技术不变量误判的是**正确性**（**硬约束**，每条配可执行检查 = 测试 / 断言 / lint，破坏即自动拦）。
> **为什么单独建**：ConnectManager 类「已修复又被改坏」的回归，根因是不变量没显式声明 + 测试硬拦——compaction / 换会话 / AI 自信重推都会丢它。**1 条不变量也会丢，与规模无关**（这是它不绑规模阈值、现在就值得落的理由）。
> **定位**：与 `business-rules.md` / `patterns.md` / `decisions/` 并列，属「约束分治 4 类」里的**不变量类**（见 `进阶/记忆库体系.md`）。**进 git**（制度资产）——git 纳管政策见 [MAINTENANCE.md](MAINTENANCE.md)「git 分层」节。

---

## 启用信号（项目是否需要本文件）

满足任一就值得激活（按项目实际，不强求）：

- 出现过「已修复的 bug 在后续改动中被再次修坏」（回归）
- 有复杂状态机 / 跨平台易碎点 / 并发或时序敏感逻辑
- 有「看起来可以改、但一改就崩」的硬性技术约束

无上述信号的小项目，可不激活（本文件留空或删）。

---

## 不变量格式

每条按此模板（**与 business-rules 不同**：去「可达性判定」，加「可执行检查」+「易违反场景」）：

```markdown
## INV-<域>-<序号> <一句话不变量>
- **不变量**：<任何时刻任何路径都必须成立的技术事实，肯定句>
- **可执行检查**：<测试 / 断言 / lint——破坏即自动拦截；已有测试标 `test:<路径>`，没有的标「待补」并尽快补>
- **易违反场景**：<什么改动最容易破坏它（重构 / 改名 / 换实现 / 性能优化时）>
- **关联**：<相关代码路径；这些变更时必须回头核对>
- **溯源**：<何时确认、关联的回归 case 或需求>
```

> **「可执行检查」是本文件存在的意义**：不变量天然可测，文档 + 测试双保险才有硬拦。只有文档没测试 = 又回软约束防不住破坏的老路。每条至少声明检查意图。

## 示例（演示格式，本项目替换为实际不变量）

> 以下为格式示例，占位不指任何真实代码。

### INV-CONN-001 <示例：连接管理器单实例>
- **不变量**：ConnectManager 全局唯一实例；重复初始化直接复用，不新建连接
- **可执行检查**：`test:<path/to/connect_manager_test>`（断言二次获取返回同实例）；并发场景「待补」
- **易违反场景**：重构单例 / 为「性能」加缓存层 / 多入口初始化时最易破坏
- **关联**：`<path/to/connect_manager>`；单例 / 初始化逻辑变更时核对
- **溯源**：ConnectManager 在某平台重复创建导致连接泄漏的回归 case

## 读取时机（文档不会自动被读）

| 时机 | 绑定 | 效果 |
|---|---|---|
| **改约束密集模块前** | 记忆库体系「实现新功能前」流程：触及关联代码时读本文件 | 改前知道有哪些不变量不能破 |
| **方案评审前** | 方案评审闭环 plan-reviewer 对照本文件查不变量破坏 | 方案阶段就拦 |
| **代码审查前** | 审查纪律 Gate：查约束含 INVARIANTS | 改了关联代码时检查 |
| **会话级兜底** | 项目 `CLAUDE.md` 声明「改硬约束模块前读 INVARIANTS」 | 不走上述流程也先读 |

## 取代与生命周期

- **被取代不删**：旧不变量被新规则取代，标「⚠️ 被 INV-YYY 取代 + 原因 + 日期」
- **取代记录开 `decisions/`**：长篇「为什么新取代旧」放 `decisions/`（格式见 `进阶/记忆库体系.md`），本文件只留极简指针——避免规则文件堆积「为什么」
- **失效留痕**：业务 / 技术变更使不变量不再成立，标失效原因 + 日期，溯源不丢
- **编号不复用**

---

## 维护

- **关联代码变更时核对**：每条写「关联」；关联代码重构 / 改名时，按关联找不变量核对是否仍成立
- **测试与文档同步**：「可执行检查」标的测试删除 / 改名时，回头更新本条
- **定期收敛（防漂移）**：季度复盘扫一遍活跃不变量——约束漂移（有约束但错的、测试锁旧约束掩盖）只能人肉收敛，无银弹
