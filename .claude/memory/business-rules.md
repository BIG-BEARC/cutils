# 业务真实规则（business-rules）

> **这是什么**：记录项目里「业务实际怎么运转」的事实——那些**不在代码里、只在需求方脑子里**的业务真相。审查 / 方案评审时，AI 先读这里，命中规则就能自己判定可达性，不必每条都问需求方。
> **定位**：本文件是「**业务事实记录**」，不是「开发规约」。规约开发行为是 `CLAUDE.md` / `进阶/` 的职责；本文件只记录业务现状。与 `patterns.md`（代码怎么写）、`decisions/`（为什么这么设计）正交，互不重叠。体系定位见 `进阶/记忆库体系.md`。
> **进 git**（制度资产，随仓）——git 纳管政策单一权威见 [MAINTENANCE.md](MAINTENANCE.md)「git 分层」节。

---

## 为什么需要

审查纪律的「业务可达性 Gate」能拦偷懒型误判，但拦不住**无知型误判**——AI 不知道「某字段后端不回传」「某业务场景不存在」，于是把不可达的路径当 Critical 报。根因是缺业务知识，不是缺规则。

本文件把业务真相外化：误判一次 → 沉淀一条 → 之后同类问题自动消音。详见 `进阶/审查与复核纪律.md`「业务可达性 Gate」。

---

## 规则格式

每条规则按此模板：

```markdown
## WR-<域>-<序号> <一句话结论>
- **结论**：<业务实际怎么运转，肯定句>
- **可达性判定**：<审查 / 方案遇到什么情况 → 判 L0 / L1 / L2 或不可达>
- **边界 / 反例**：<什么条件下本规则不适用>
- **关联**：<相关代码路径 / 接口 / 入口；这些变更时必须回头更新本条>
- **溯源**：<何时、何场景确认的；关联的误判 case 或需求>
```

## 示例：称重域（演示格式，本项目替换为实际业务域）

> 以下 3 条由一个连续称重功能的审查误判沉淀而来，**仅作格式示例**。称重 / 字段 / 路径均为占位，本项目按实际业务改写；溯源见 `进阶/审查与复核纪律.md`「案例 Why」。

### WR-WEIGH-001 称重字段后端不回传
- **结论**：称重接口后端【不回传】称重字段；试算回灌会清空；删菜恒走 fallback
- **可达性判定**：若审查发现「代码读称重字段做累加」→ **L0**（恒为空，不可达），降级 / 撤条
- **边界 / 反例**：若后端契约改为回传，本规则失效（标 ⚠️ 已失效，见维护规则）
- **关联**：`<path/to/weigh_service>`、接口 `<api/weigh>`；后端契约变更时更新本条
- **溯源**：称重审查误判 case

### WR-WEIGH-002 某核销场景无称重菜
- **结论**：某核销入口对应的业务场景，业务上根本不含称重菜
- **可达性判定**：若审查报「该核销入口绕过称重锚定」→ 业务组合不存在，**不可达**，撤条
- **边界 / 反例**：核销场景扩品到含称重菜时，本规则失效
- **关联**：`<path/to/verify_entry>`；核销场景配置变更时更新
- **溯源**：称重审查误判 case

### WR-WEIGH-003 数量入口已 UI 拦截
- **结论**：数量按钮对相关商品已禁用（`isGray` / `disabled`），点击被拦截
- **可达性判定**：若审查报「数量守卫缺失」→ UI 层已拦截，**不可达**，撤条
- **边界 / 反例**：禁用条件解除时，本规则失效
- **关联**：`<path/to/count_button>`；禁用逻辑变更时更新
- **溯源**：称重审查误判 case

## 读取时机（关键：文档不会自动被读）

「写进本文件」≠「AI 会读」。必须把读取绑到时机：

| 时机 | 绑定 | 效果 |
|---|---|---|
| **审查前** | 审查纪律「业务可达性 Gate」加硬步骤：定级前先查本文件 | 命中规则就不报 |
| **方案评审前** | 方案评审闭环 plan-reviewer 对照本文件查业务假设 | 方案阶段就拦 |
| **会话级兜底** | 项目 `CLAUDE.md` / `项目附录.md` 声明「涉域时先读本文件」 | 不走审查 / 方案评审也先读 |

主干是前两个，第三个兜底。

## 维护规则

- **关联代码变更时更新**：每条规则写「关联」；关联的代码 / 接口 / 入口变更时，按关联找规则同步改
- **失效不删**：业务变更使旧规则失效，标「⚠️ 已失效 + 原因 + 日期」——溯源不丢，避免重蹈
- **编号不复用**：WR-WEIGH-001 失效，新规则用 004，不回收 001
- **起草与确认**：AI 可从代码 / 接口**推测起草**，但**必须需求方确认**才定稿（业务真相只在需求方脑子里）

## 沉淀闭环

```text
误判发生 → 需求方否决（撤条，保留「经确认业务不可达」）→ 同时沉淀一条进本文件
↑                                                                       ↓
└────────── 下次同类问题，AI 读到规则，不再误判 ←──────────────────────────┘
```

第 1 次踩坑花需求方一次否决精力，**换来之后所有同类问题自动消音**。
